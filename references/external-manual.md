# 对外操作手册模式（external-manual）

面向客户最终用户的操作手册，输出可直接交付、可被照做的步骤说明。它复用 `product-guide` 的取证与功能结构，同时替换三件事：叙事口径、事实标准、截图规范。

## 与 product-guide 的关系

| 维度 | product-guide（对内） | external-manual（对外） |
|---|---|---|
| 读者 | 研发、实施、业务内部人员 | 客户最终用户、甲方管理员 |
| 目标 | 理解本次迭代，并学会配置/操作 | 按步骤完成某个业务动作 |
| 事实来源 | 录屏证据；未演示内容可标“待确认” | 内容必须在系统内可复现验证；截图允许录屏定点抽帧 |
| 视频位置 | 保留时间戳，便于回看 | 不出现任何时间戳或“视频位置”字样 |
| 迭代叙事 | “本次变化 / 解决的问题”是核心 | 正文不写迭代叙事；保留独立的“本次新增/变更”章节 |
| 内部问题 | 演示限制、研发问题、证据缺口要写清 | 不出现；对外不留“待确认” |
| 截图 | 定点截帧，允许带内部信息 | 干净、脱敏、带引导标注，统一风格 |
| 术语 | 内部叫法可用 | 对外产品术语，需要术语表统一 |
| 质量门禁 | A/B 级均可，缺口列清单 | 只接受 A 级；缺口不发布，宁缺毋滥 |

结构可复用 `功能效果 → 配置 → 台账 → 应用 → 结果输出 → 异常排查`，但组织顺序优先按“用户任务”而不是“系统模块”。

**对外模式不含“验收检查表/验收场景”**：验收属于内部交付与质量范围，不写进客户手册；如客户需要验收清单，另行提供内部验收表，不要混入对外正文。

默认交付**一本通**（单册），不按管理员册、业务操作册、移动端册拆分；客户确需分册时另行确认。

## 事实标准

- 每个步骤必须在系统里实际走通，不能只依据讲解人口述。
- 录屏中的演示限制、测试环境问题、研发缺陷不得写入对外手册。
- 讲解没有说明、页面也没有体现的规则，不补造；必须确认后再写。
- 涉及权限、并发、历史数据影响等边界条件时，必须写明适用范围（例如“适用于 X 版本及以上”）。

## 结构模板

```text
功能说明（这个功能解决什么业务问题）
前置条件（权限、基础数据、设备/配置依赖）
操作步骤（每步：入口 → 操作 → 系统响应 → 校验点）
结果查看（在哪里看到结果、如何导出/打印）
常见问题（客户实际会遇到的，可自助解决）
附录（字段说明、术语表、版本说明）
```

- 一步只做一件事；连续操作不超过 7 步时用编号步骤，超过时按“阶段 + 步骤”两级组织。
- 每步都要有明确的结果，避免“点击保存”这类没有反馈描述的步骤。
- 涉及配置对象时，先给“对象关系表”（谁引用谁），再给操作步骤。
- 章节收尾是“常见问题”，**不写验收检查表/验收场景**（内部内容）。

## 写作规则

- 不使用“从画面上看”“视频中演示”“本次迭代新增”等内部视角表达。
- 不使用“待确认”“视频未展示”等未完成状态；未确认内容不进入手册。
- 术语与产品对外名称一致；同一概念只用一个词。
- 表格优先：字段说明、角色权限、状态流转、错误码都用表格。
- 每章控制在可打印范围内，避免超长无分页的连续段落。

## 截图规范

对外手册的截图允许使用录屏定点抽帧，也可以在干净演示环境中重新截图；两种来源都必须经过四道处理，缺一不可：

| 处理 | 要求 |
|---|---|
| 裁剪 | 去掉桌面、任务栏、浏览器标签和地址栏、录制水印，只保留系统页面 |
| 脱敏 | 遮住内网地址、人名、手机号、账号、客户业务数据、测试数据 |
| 标注 | 关键入口/字段/操作位置加红框、编号和箭头，与正文步骤号对应 |
| 放大 | 文字过小的区域做局部放大 inset，不要直接放大整张图导致模糊 |

- 一张图只表达一个操作意图；步骤与截图一一对应。
- 截图必须从录制原片按原生分辨率截取（不要用已压缩的缩略图），成品宽度不低于 1400 px，保证客户缩放打印后文字仍可辨认。
- 原图与成品分开存放：原图放 `assets/raw/`，处理后的成品放 `assets/images/`。
- 标注坐标必须存成 JSON（`assets/annotations/*.json`），截图重拍后可用同一份标注重放。
- 全册统一样式：红色 `#E5392E`、线宽 3 px、圆角 6、编号圆标半径 13；同一本手册只用这一套。

## 脱敏清单

默认最小脱敏（未特别要求时）：**只模糊企业名称**（页面头部 + 组织树）；内网地址、手机号、共享屏幕水印如出现必须遮挡；姓名、工号、业务数据按项目要求决定（演示环境数据可保留）。

发布前逐项检查：

| 对象 | 处理 |
|---|---|
| 企业名称（页面头部、组织树） | 模糊（默认必做） |
| 内网地址、端口、系统域名 | 裁掉浏览器地址栏；页面内出现的用色块或模糊遮挡 |
| 手机号、身份证号、共享屏幕水印、会议参会人标识 | 遮挡或裁剪 |
| 客户真实业务数据、合同编号、车牌等 | 按客户要求脱敏或替换为示例数据 |
| 浏览器标签、书签、任务栏图标 | 裁剪掉 |

## 标注规格

- 全册统一样式：红色 3 px 圆角框 + 箭头 + ①②③ 编号；需要时配局部放大（放大镜）。
- 只标操作点（按钮/输入框/下拉/tab/提交入口）；结果页、报表页、清单页不标注。
- 每张图 ≤2 处标注；确实需要 3 处时不超过 3 处，超过说明这张图应拆图。
- 编号 `①②③` 与正文步骤号一一对应；图内只放编号和 2–8 字短标签，完整说明放正文。
- 箭头从标签指向目标控件；引线不得覆盖文字。
- 目标控件很小或页面文字过小时，用 `inset` 做局部放大，不要放大整张图。
- 禁止用标注遮盖敏感信息（脱敏用色块或模糊，不用红框盖）。

## 标注自检（必须执行）

图片生成后不能直接发布，必须逐张自检：

1. 用 `--qa` 生成每个红框区域的放大图（`<out>/qa/*-qa1.png`）：

   ```bash
   python3 "${CLAUDE_SKILL_DIR}/scripts/annotate.py" assets/annotations/manual.json --qa
   ```

2. 逐张查看 QA 放大图，确认：
   - 红框完整包住目标控件，没有偏一行、偏一列或切到文字；
   - 编号与正文步骤号一致；
   - 箭头指向框内目标，没有压住文字或被其他元素挡住；
   - 标签、放大镜没有遮住需要阅读的内容。
3. 发现偏差就改 JSON 坐标，重跑后**重新自检**，不能凭“看起来差不多”放过。
4. 常见错误：页签差一列（框到相邻页签）、框的下边缘切到数值行、标签浮在内容上、箭头穿过正文。

### annotate.py 用法

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/annotate.py" assets/annotations/manual.json
```

规格示例：

```json
{
  "defaults": {"color": [229, 57, 46], "width": 3, "font_size": 24},
  "jobs": [
    {
      "src": "assets/raw/01-子区域管理.png",
      "out": "assets/images/01-子区域管理.png",
      "ops": [
        {"op": "crop", "mode": "bbox", "trim_bottom": 30},
        {"op": "mask", "rect": [0, 0, 400, 40], "mode": "blur"},
        {"op": "box", "rect": [120, 210, 260, 250], "badge": "1", "fill_alpha": 28},
        {"op": "arrow", "from": [420, 230], "to": [265, 228]},
        {"op": "label", "at": [430, 230], "text": "点击新增", "bg": [0, 0, 0, 160]}
      ]
    }
  ]
}
```

支持的操作：`crop`（bbox/rect、trim、pad）、`scale`、`mask`（solid/blur/pixelate）、`box`（圆角框 + 可选填充 + 编号）、`arrow`、`label`（可选编号、背景）、`inset`（局部放大）。所有操作按顺序作用于同一张图，输出到 `out`。


## 取帧与资产版本（根治规则）

截图反复出现“过渡帧、半透明弹窗、看到的不是最新图”，根因是抽帧只取单点时间、图片同名覆盖、门禁不校验状态。按下面三条根治：

1. **抽帧：连拍 + 平台期 + 状态断言**，不用单点时间戳猜帧：
   `python scripts/stable_frame.py --video 视频 --time HH:MM:SS --window 4 --fps 6 --out 选定帧.png --report 证据.json --assert-region x1,y1,x2,y2 --assert-white-min 0.55`
   平台期帧才代表稳定 UI 状态；状态断言不过（弹窗区域不够白/文字不清）即判失败，换窗口或重录，不进入后续流程。
2. **资产版本化**：图片文件名带版本号（`-v5`），文档引用带版本号；每次重生成升版本并删除旧文件，杜绝同名缓存看到旧图。
3. **清单留证**：`assets/manifest.json` 记录每张图的 sha256、原图、来源视频/时间点、生成时间和取帧证据；门禁核对“引用文件 = manifest 最新版本、哈希一致”。

## 图片质量门禁（发布前必跑）


图片不能“生成完就交”，必须逐张过门禁并留档。任何一项不通过都阻断发布：

| 步骤 | 检查 | 通过标准 |
|---|---|---|
| 1 取图 | 来源 | 从录制原片原生分辨率抽帧，非二次压缩 |
| 2 裁剪 | 环境清理 | 无桌面、任务栏、浏览器地址栏、分享水印 |
| 3 可读性 | 遮挡与浮窗 | 无无关浮窗遮挡主体；浮窗必须完全展开、不透明、文字可读 |
| 4 内容 | 图注一致性 | 页面标题 / tab / 弹窗标题与章节步骤、图注一致 |
| 5 清晰度 | 分辨率 | 成品宽度 ≥ 1400 px，关键文字可辨认、无放大模糊 |
| 6 引用 | 完整性 | 正文引用的图片全部存在，无缺失、无重复 |
| 7 留档 | 记录 | 门禁报告 + 标题条复核图 + 逐图登记表存入项目 |

**浮窗处理原则：** 浮窗是正文讲解对象时，必须选择浮窗完整展开、不透明、文字可读的帧；不能因为没有干净帧就换成没有浮窗的图。只有浮窗与讲解无关时才裁剪或换帧。

**直接弃用的画面：**

- 无关浮窗（弹窗、抽屉、气泡）遮挡页面主体；
- 浮窗半透明、正在加载或处于动画中间态，文字看不清；
- 截图时鼠标、输入法、通知遮挡关键字段；
- 表格只有“暂无数据”且空态不是讲解对象；
- 页面切换、滚动过程中的过渡帧。

遇到这些帧，换更稳定的帧或要求重新录制，不要靠放大、锐化去救。

工具：

```bash
# 引用校验 + 分辨率校验 + 生成标题条复核图
python3 "${CLAUDE_SKILL_DIR}/scripts/check_images.py" \
  --doc 操作手册.md --manifest assets/manifest.json --require-page-id --min-width 1400 \
  --report-out 运行产物/gate/image-gate.json \
  --title-out 运行产物/gate/titles.jpg

# 文档级门禁：引用=manifest、版本化、page_id、标注策略、对外结构（不含验收检查表）
python3 "${CLAUDE_SKILL_DIR}/scripts/doc_lint.py" \
  --doc 操作手册.md --manifest assets/manifest.json --images-dir assets/images \
  --require-versioned --require-page-id \
  --annotations assets/annotations/manual.json \
  --external --report-out 运行产物/gate/doc-lint.json
```

- `--title-out` 生成的拼接图包含每张图顶部标题/tab 条，**必须人工逐条比对图注**；
- 核对发现错配就换图、改图注或删图，然后重新跑完整门禁；
- 报告与登记表（图号、章节、图注、实际页面、宽度、结果）随手册存档，作为发布证据。

## 质量门禁

交付前逐项检查，任何一项不通过都不能发布：

| 检查项 | 通过条件 |
|---|---|
| 功能目标 | 说明了解决的业务问题和最终效果 |
| 前置条件 | 权限、基础数据、依赖配置齐全且可验证 |
| 操作步骤 | 每步可执行、有结果、顺序正确 |
| 结果输出 | 有结果页面、打印或导出说明 |
| 截图完整性 | 每步都有对应截图，四道处理全部完成 |
| 标注 | 编号与正文步骤一致，无遮挡正文或敏感信息 |
| 脱敏 | 企业名称已模糊；无内网地址、手机号、水印；人名/业务数据按项目要求 |
| 章节结构 | **不含验收检查表/验收场景**（验收属内部内容） |
| 术语 | 与对外术语表一致，全文统一 |
| 证据边界 | 没有“待确认”“视频未演示”等未完成内容 |
| 版本 | 标明适用产品版本与更新日期 |

## 产物结构

```text
manual/
├─ 操作手册.md
├─ assets/
│  ├─ raw/              # 原始截图（内部留档，不对外）
│  ├─ images/           # 处理后的成品截图
│  └─ annotations/      # 标注 JSON，可重放
└─ 术语表.md
```

交付格式按需转换（Markdown → Word / PDF / 在线帮助）；发布前由产品/客户成功确认版本与承诺口径。
