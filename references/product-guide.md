# B端产品录屏图文说明

用户希望通过图文笔记快速理解系统功能并学习实际用法时，使用本模式。不要按视频场景流水记账，应先识别功能边界，再围绕业务闭环组织内容。

## 信息来源关系

- 逐字稿负责功能目的、业务逻辑、处理流程和讲解人的明确判断。
- 页面画面补充菜单路径、页面名称、字段、按钮和操作状态。
- 参考手册只用于补充已有产品结构或写法；不能覆盖视频中明确说明的本次迭代事实。
- 正文直接写用户需要执行和理解的内容，不写“从画面可以确认”“根据截图推断”等取证过程。
- 页面没有展示、讲解人没有说明的规则，列入待确认，不按产品经验补造。

## 功能组织模型

每个功能优先组织为：

```text
功能效果 → 配置 → 台账 → 应用 → 结果输出 → 异常排查 → 验收
```

没有独立报表时使用“结果输出”，不要把打印预览强行称为报表。

## 两层阅读结构

第一层帮助读者快速判断是否需要继续阅读：

- 本次变化；
- 解决的问题；
- 配置端、应用端和输出端；
- 最终结果。

第二层指导实际使用：

- 完整业务流程；
- 前置数据和权限；
- 菜单路径；
- 配置字段及其业务作用；
- 台账维护；
- 实际办理步骤；
- 结果查看和输出；
- 常见问题及验收。

## 表达方式

遵循“字不如表、表不如图”，但图片不能替代必要文字：

- 三个以上连续步骤优先使用流程；
- 重复字段、多个对象或差异关系优先使用表格；
- 故障、原因和处理方式使用排查表；
- 验收内容使用“场景—预期结果”表；
- 段落只保留因果关系、边界条件和无法表格化的业务规则；
- 用户不观看视频、只读正文，也应能理解功能并完成操作。

## 截图完整性

配置型功能优先形成以下截图组：

| 页面类型 | 所需证据 |
|---|---|
| 配置 | 台账列表＋新增或编辑表单 |
| 查询 | 查询条件＋查询结果 |
| 业务办理 | 操作前状态＋关键填写页＋提交结果 |
| 审批 | 当前节点＋完成状态 |
| 输出 | 输出入口＋最终预览 |
| 异常 | 异常提示或异常结果 |

视频未展示某一画面时，不用其他页面冒充。将其记入缺失截图清单，降低交付等级，必要时提出定点补拍建议。

选择截图时排除黑屏、白屏、加载中、桌面切换、会议头像页、动画中间态、文字模糊和高度重复画面。页面刚切换时优先检查操作后1秒、3秒和5秒的稳定画面。

遵守当前工作区关于图片查看并发的要求；如果要求一次只看一张，就不得并行查看图片。

## 证据与质量门禁

先读取 `product-evidence.json`，再回看关键逐字稿和截图。正式交付前检查：

| 检查项 | 通过条件 |
|---|---|
| 功能目标 | 说明解决的问题和最终效果 |
| 菜单路径 | 补充到最终页面或明确缺失 |
| 配置对象 | 字段、来源和作用明确 |
| 台账维护 | 查询、新增、编辑、导入等实际能力有说明 |
| 业务应用 | 说明角色、时点和操作 |
| 结果输出 | 有结果页面、打印或导出说明 |
| 截图完整性 | 关键步骤具备对应截图，缺失项已列出 |
| 术语质量 | ASR疑似错词已经校正或标注 |
| 证据边界 | 未确认内容没有写成产品规则 |
| 隐私 | 对外材料已检查内网地址、姓名、账号和业务编号 |

交付等级：

- A级：具备配置、台账、应用、输出的完整操作证据；
- B级：业务逻辑完整，但缺少部分配置或结果截图；
- C级：只能形成视频摘要，不足以指导实际操作。

## 中间产物

产品模式至少保留：

- 原始和标准化逐字稿；
- 转写空档；
- 操作关键词锚点；
- 原始场景帧；
- 操作前后候选帧；
- 缺失截图和待确认项；
- 最终采用截图。
